## 001｜逻辑表达式求值

记录日期：2026-11-13  
语言：Java  
关键词：栈、表达式求值、BufferedReader、位运算

### 简略题意

输入 T 个合法逻辑表达式，包含 0、1、括号以及 !、&、|、^、->，输出每个表达式的值。

每个运算都有完整括号，例如 `(!1)`、`(1&0)`、`(0->1)`。所有表达式的总长度不超过 10^6。

示例：`(!(!(1^1)))` 的结果是 0。

### 解题思路

- 我想到了遇到右括号就算。
- 我有点不确定的点是怎么把东西存数组里。（最一开始，然后就问ai了）
- 完全没想到模拟栈。


从左到右扫描，用字符数组模拟栈：

1. 遇到 `(`，直接忽略。
2. 遇到 `>`，直接忽略；用 `-` 代表整个 `->`。（这点没想到）
3. 遇到数字或运算符，入栈。
4. 遇到 `)`，弹出右操作数 b 和运算符。若为 `!`，直接取反；否则再弹出左操作数 a，完成运算。将结果重新入栈。
5. 扫描结束，栈中剩下的字符就是答案。

### Java 参考代码

```java
import java.io.*;

public class Main {
    public static void main(String[] args) throws IOException {
        BufferedReader br = new BufferedReader(
                new InputStreamReader(System.in));
        int t = Integer.parseInt(br.readLine().trim());
        StringBuilder output = new StringBuilder();

        while (t-- > 0) {
            String s = br.readLine().trim();
            char[] stack = new char[s.length()];
            int top = 0; // 指向下一个可写入的位置

            for (int i = 0; i < s.length(); i++) {
                char c = s.charAt(i);
                if (c == '(' || c == '>') continue;

                if (c != ')') {
                    stack[top++] = c;
                    continue;
                }

                int b = stack[--top] - '0';
                char op = stack[--top];
                int result;

                if (op == '!') {
                    result = b ^ 1;
                } else {
                    int a = stack[--top] - '0';
                    switch (op) {
                        case '&': result = a & b; break;
                        case '|': result = a | b; break;
                        case '^': result = a ^ b; break;
                        default: result = (a ^ 1) | b; break; // ->
                    }
                }
                stack[top++] = (char) ('0' + result);
            }
            output.append(stack[0]).append('\n');
        }
        System.out.print(output);
    }
}
```

### 我这次问过的问题

`int a = stack[--top] - '0'`为啥要减0：
 
这里减的是字符 '0'，不是数字 0，目的是把字符转换成整数。

因为 stack 是 char[]，存进去的是字符 '0' 或 '1'。字符参与运算时，使用的是它的编码值：

- '0' 的编码是 48
- '1' 的编码是 49

所以减去 '0' 后：

```java
'0' - '0'  // 48 - 48 = 0
'1' - '0'  // 49 - 48 = 1
```

### 能从这道题学到什么

- 模拟栈（我一开始想的是把东西先存再操作，其实可以同时）
- 怎么把一串字符串拆成字符数组
- 那些逻辑运算符的电脑表达。（蕴含，还有取反）


1. **栈适合处理嵌套结构。** 内层表达式先结束、先计算，符合栈“后进先出”的特点。遇到括号匹配、嵌套计算，可以先考虑栈。
2. **善用题目保证。** 所有运算都有括号，因此不需要处理运算符优先级，也不需要复杂的语法分析。
3. **数组模拟栈。** `stack[top++] = c` 表示先写入再移动指针；`stack[--top]` 表示先移动指针再取出栈顶。栈中元素个数始终为 `top`。
4. **注意操作数顺序。** 先弹出来的是右操作数 b，再弹出的是左操作数 a。对于 `a -> b`，左右不能交换。
5. **理解蕴含。** `a -> b` 等价于 `非 a 或 b`，只有 a=1、b=0 时结果为 0。四种情况依次为：0->0=1、0->1=1、1->0=0、1->1=1。原题真值表排版有误，以此为准。
6. **0/1 可以用位运算表示逻辑运算。** `a & b`、`a | b`、`a ^ b` 分别对应与、或、异或。对于只可能是 0/1 的值，`a ^ 1` 可以取反；不能用 `~a`，因为它会翻转整数的所有二进制位。
7. **字符和数字需要转换。** `c - '0'` 把字符 '0'/'1' 转为整数；`(char) ('0' + result)` 把结果转回字符。
8. **数据规模决定写法。** 长度可达 10^6，递归求值可能因嵌套过深而栈溢出。迭代加显式栈更稳妥；每个字符最多入栈、出栈一次，时间 O(n)、空间 O(n)。

## 002｜后缀逻辑表达式：单个变量取反后的结果

记录日期：2026-11-14  
语言：Java  
关键词：后缀表达式、栈、表达式树、预处理、变化的传递

### 简略题意

给定一个只包含变量、`&`、`|`、`!` 的后缀表达式，以及各变量的初始值。每个变量恰好出现一次。

每次询问将一个变量取反，求整个表达式的结果。每次修改都是临时的，不影响后续询问。

表达式长度最多 10^6，变量和询问数最多 10^5。

例如 `x1 x2 & x3 |` 表示 `(x1 & x2) | x3`。

### 和侧边聊天中学过的内容联系起来

侧边《DSAA问题解答》中，之前问过“这题让干啥啊”“所以是写程序，不是写纸质答案”，当时讨论的是 Question 8.5 后缀整数计算器。那题用 `3 5 +` 表示 `3 + 5`，重点是理解输入已经是后缀表达式，只需要从左到右处理，不需要再做中缀转后缀。

这道题沿用同一套栈操作，只是把整数运算换成逻辑运算，并增加多次取反询问。

| 对比 | 后缀整数计算器 | 这道题 |
| --- | --- | --- |
| 输入形式 | `3 5 +` | `x1 x2 &` |
| 遇到操作数 | 入栈 | 创建变量节点，节点编号入栈 |
| 遇到二元运算 | 弹出两个值，算完入栈 | 弹出两个节点编号，创建运算节点，记录孩子和结果，再入栈 |
| 为什么保留树 | 只求一次结果，无需保留 | 后面要判断一个变量的变化会经过哪些运算 |

这里不是把之前计算器的输入格式照搬过来。本题第一行是一整行表达式，然后才是变量数、初始值和询问。读取方式必须跟着当前题目走。

后缀表达式里，运算符出现时，它需要的操作数已经准备好了。因此不需要等右括号，看到运算符就可以处理；`!` 只弹一个，`&`、`|` 弹两个。

### 我这次问过的问题：咋想出来的啊？

重点不是先记住代码，而是理解下面这条推导路线。

#### 第一步：先想暴力，再看哪里重复

最直接的方法是每次把变量取反，然后用栈重新计算整个表达式，再恢复变量。

但每次计算都要 O(L)，q 次就是 O(Lq)，数据最大时会超时。这里 L 是表达式长度。

下一步应该问：只改一个变量，真的需要把所有地方都重算吗？

#### 第二步：只有一条路径可能发生变化

把 `(x1 & x2) | x3` 画成表达式树：

```text
        |
       / \
      &   x3
     / \
    x1 x2
```

修改 x1，只有 `x1 → & → |` 这条路径上的结果可能变化。其他子树没有改变。

这就是建树的原因：需要保留每个运算和它的操作数之间的关系。上一题栈里存值就够了，这题栈里要存节点编号。

#### 第三步：变化可能被运算阻断

| 运算 | 一个孩子的变化能向上传递的条件 |
| --- | --- |
| `A & B` | 另一个孩子的值是 1 |
| `A \| B` | 另一个孩子的值是 0 |
| `!A` | 一定能传递 |

- `A & 0`：无论 A 怎么变，结果始终是 0，变化被挡住。
- `A & 1`：结果跟着 A 变化。
- `A | 1`：无论 A 怎么变，结果始终是 1，变化被挡住。
- `A | 0`：结果跟着 A 变化。
- `!A`：A 翻转，结果也会翻转。

因此，只需要判断变量到根节点的路径上，有没有地方阻断变化。

#### 第四步：从根往下，一次标记所有变量

每次询问都向上走一遍，树很深时仍然会慢。所以反过来，从根向下预处理。

根节点的值改变，最终答案当然改变。对于一个已经确定能影响最终答案的节点：

- 如果是 `&`，当另一边为 1 时，标记当前孩子。
- 如果是 `|`，当另一边为 0 时，标记当前孩子。
- 如果是 `!`，直接标记它的孩子。

标记传到哪个变量，就说明这个变量取反会让最终结果取反。没有标记的变量取反后，最终结果不变。

```java
int answer = original ^ (important[index] ? 1 : 0);
```

这条思路能成立，关键在于题目的两个条件：

- **每个变量只出现一次**：一个变量到根只有一条路径，不会同时改变另一边的子树。
- **每次修改是临时的**：每次都以初始值为基础，标记只需计算一次。

### 用样例理解

对于 `(x1 & x2) | x3`，初始值为 `1、0、1`，原结果为 1。

| 取反的变量 | 变化如何传递 | 最终答案 |
| --- | --- | --- |
| x1 | 在 & 处被 x2=0 阻断 | 1 |
| x2 | 能经过 &，但在 \| 处被 x3=1 阻断 | 1 |
| x3 | 另一边 x1 & x2=0，变化能传到根 | 0 |

### 把思路和代码里的数组对应起来

#### 1. 不创建 Node 对象，也能存一棵树

把节点编号当成数组下标，同一个下标对应同一个节点：

| 数组 | 保存什么 |
| --- | --- |
| `op[id]` | 节点类型：变量、与、或、非 |
| `left[id]` | 运算节点的左孩子编号；变量节点则借用它保存变量下标 |
| `right[id]` | 二元运算节点的右孩子编号 |
| `value[id]` | 这个节点所代表的子表达式在初始状态下的值 |
| `stack` | 目前已经处理好、等待参与后续运算的节点编号 |
| `affect[id]` | 单独翻转这个节点的结果，是否会使最终答案翻转 |
| `important[i]` | 变量 xi 取反，是否会使最终答案翻转 |

`affect` 记录的是“能否影响答案”，不是节点当前的值。一个值为 0 的节点，也可能有 `affect[id] == true`。

#### 2. 变量下标和节点编号不是一回事

扫描 `x1 x2 & x3 |` 时，每创建一个节点，`count` 加一：

| 扫描到 | 新节点编号 id | 内容 | 初始结果（变量值为 1、0、1） |
| --- | --- | --- | --- |
| x1 | 1 | 变量下标 1 | 1 |
| x2 | 2 | 变量下标 2 | 0 |
| & | 3 | 左孩子 1，右孩子 2 | 0 |
| x3 | 4 | 变量下标 3 | 1 |
| 或运算符 | 5 | 左孩子 3，右孩子 4 | 1 |

所以 x3 的变量下标是 3，但对应节点编号是 4。询问给的是变量下标，因此最终要查 `important[3]`。

建树时，栈的变化如下。这里存的是编号，不是 0/1 值：

```text
x1： [1]
x2： [1, 2]
& ： 弹出 2 和 1，创建节点 3，栈变为 [3]
x3： [3, 4]
| ： 弹出 4 和 3，创建节点 5，栈变为 [5]
```

#### 3. 为什么倒序遍历就能从父节点传到孩子？

运算节点总是在它的孩子之后创建，所以父节点编号一定更大。上例里根是 5，它的孩子是 3 和 4；节点 3 的孩子是 1 和 2。

按 `5、4、3、2、1` 处理，就能保证每个节点在轮到自己之前，父节点已经决定是否给它传标记。不需要节点编号相邻，只需要父节点编号大于孩子。

#### 4. 为什么经过 ! 时不用把标记取反？

计算初始值时，确实要取反：`value[id] = value[child] ^ 1`。

传递标记时，问的是“孩子变化，会不会导致父节点变化”。孩子从 0 变 1，非运算结果从 1 变 0；孩子从 1 变 0，结果从 0 变 1。两种情况都发生变化，所以直接传递 `true`。

### Java 参考代码

```java
import java.io.*;
import java.util.StringTokenizer;

public class Main {
    static BufferedReader br = new BufferedReader(
            new InputStreamReader(System.in));
    static StringTokenizer st;

    static int nextInt() throws IOException {
        while (st == null || !st.hasMoreTokens()) {
            st = new StringTokenizer(br.readLine());
        }
        return Integer.parseInt(st.nextToken());
    }

    public static void main(String[] args) throws IOException {
        String s = br.readLine();
        int n = nextInt();
        int[] initial = new int[n + 1];
        for (int i = 1; i <= n; i++) initial[i] = nextInt();

        int capacity = s.length() + 1;
        char[] op = new char[capacity];
        int[] left = new int[capacity];
        int[] right = new int[capacity];
        int[] value = new int[capacity];
        int[] stack = new int[capacity];
        int top = 0, count = 0;

        for (int i = 0; i < s.length(); i++) {
            char c = s.charAt(i);
            if (c == ' ') continue;

            if (c == 'x') {
                int index = 0;
                while (i + 1 < s.length()) {
                    char digit = s.charAt(i + 1);
                    if (digit < '0' || digit > '9') break;
                    index = index * 10 + digit - '0';
                    i++;
                }
                int id = ++count;
                op[id] = 'x';
                left[id] = index; // 叶子节点用 left 保存变量下标
                value[id] = initial[index];
                stack[top++] = id;
            } else if (c == '!') {
                int child = stack[--top];
                int id = ++count;
                op[id] = '!';
                left[id] = child;
                value[id] = value[child] ^ 1;
                stack[top++] = id;
            } else {
                int b = stack[--top];
                int a = stack[--top];
                int id = ++count;
                op[id] = c;
                left[id] = a;
                right[id] = b;
                value[id] = c == '&'
                        ? value[a] & value[b]
                        : value[a] | value[b];
                stack[top++] = id;
            }
        }

        int root = stack[0];
        int original = value[root];
        boolean[] affect = new boolean[count + 1];
        boolean[] important = new boolean[n + 1];
        affect[root] = true;

        // 父节点比孩子后创建，因此倒序可以先处理父节点。
        for (int id = count; id >= 1; id--) {
            if (!affect[id]) continue;
            if (op[id] == 'x') {
                important[left[id]] = true;
            } else if (op[id] == '!') {
                affect[left[id]] = true;
            } else {
                int a = left[id], b = right[id];
                if (op[id] == '&') {
                    if (value[b] == 1) affect[a] = true;
                    if (value[a] == 1) affect[b] = true;
                } else {
                    if (value[b] == 0) affect[a] = true;
                    if (value[a] == 0) affect[b] = true;
                }
            }
        }

        int q = nextInt();
        StringBuilder output = new StringBuilder();
        while (q-- > 0) {
            int index = nextInt();
            int answer = original ^ (important[index] ? 1 : 0);
            output.append(answer).append('\n');
        }
        System.out.print(output);
    }
}
```

### 能从这道题学到什么

1. **先从暴力出发。** 不必一开始就想到最优解。先想怎么做对，再找重复计算。
2. **后缀表达式可以用栈建树。** 遇到变量创建叶子，遇到运算符弹出操作数节点，再创建父节点。
3. **栈不一定只存数值。** 为了保留结构，可以存节点编号，通过数组找到节点的信息。
4. **分析变化的影响范围。** 修改一处时，先判断哪些部分可能改变，以及变化会在哪里停止。
5. **多次询问考虑预处理。** 初始状态固定时，可以把重复判断提前算好，让每次询问变成 O(1)。
6. **建树顺序也能用于遍历。** 后缀建树时父节点编号大于孩子，正序适合从孩子计算父节点，倒序适合从父节点向孩子传递标记。
7. **读取多位变量下标。** `x123` 需要逐位累积：`index = index * 10 + digit - '0'`。

总时间复杂度 O(L+n+q)，空间复杂度 O(L+n)。全程使用迭代，避免深表达式导致递归栈溢出。

### 复习时自问

- 为什么 `A & 0` 会阻断 A 的变化？
- 为什么标记从根往下传，而不为每个变量单独向上检查？
- 如果同一个变量出现多次，这个判断方法还能直接使用吗？（不能，它可能同时改变两边。）
- 如果询问的修改会保留到下一次，还能直接使用最初的标记吗？（不能，其他子树的值可能已经改变。）

记住推导路线：**暴力重新算 → 找到变化路径 → 判断变化是否被阻断 → 一次标记所有能影响答案的变量。**

## 003｜Binary Search Tree：按课件实现六种操作

记录日期：2026-11-14

语言：Java

关键词：BST、节点引用、插入、移植删除、子树大小、排名边界

### 简略题意

动态维护一个允许重复数字的集合，实现六种操作：插入一个 x、删除一个 x、查询 x 的排名、查询第 k 小、查询严格前驱、查询严格后继。

- 排名定义为“严格小于 x 的数字数量 + 1”，x 不一定存在。
- 前驱是严格小于 x 的最大值，后继是严格大于 x 的最小值；x 不一定存在，但答案保证存在。
- 删除保证 x 存在，重复值每次只删除一个。
- 操作数不超过 10^4，必须自己实现二叉搜索树。

### 这次的学习过程

最开始的解答用数组表示节点，重复值用 cnt 记录。随后我提出：“你用之前课件里的伪代码逻辑。”因此最终采用第 9 讲课件的 Node 节点、父节点引用和 Transplant 移植删除。

课件对应位置：第 17 页 TREE-INSERT，第 20 页 TRANSPLANT，第 21 页 TREE-DELETE。最终代码中每个重复值也单独创建节点，相等时插入右子树；不再使用 cnt。

我还问了：“你这个代码里是不是写了跟题目无关的方法？”实际没有无关方法，只是六种操作需要调用一些辅助方法。

| 方法 | 为什么需要 |
| --- | --- |
| `insert`、`remove`、`rank`、`kth`、`predecessor`、`successor` | 直接对应六种操作 |
| `search` | 删除前找到一个值为 x 的节点 |
| `min` | 删除有两个孩子的节点时，寻找右子树最小节点 |
| `transplant` | 把一棵子树接到另一棵子树原来的位置，供删除调用 |
| `size`、`update` | 读取、维护子树大小，支持排名和第 k 小 |
| `nextInt` | 读取输入 |

题目要求六种操作，并不意味着程序只能有六个方法。课件的 TREE-DELETE 本身就会调用 TREE-MINIMUM 和 TRANSPLANT。

### 节点里存什么

```java
static class Node {
    int key;
    int size = 1;
    Node left, right, p;
    Node(int key) { this.key = key; }
}
```

- `key`：这个节点存的数字。
- `left`、`right`：左右孩子的引用。
- `p`：父节点引用，对应课件的 parent。
- `size`：以当前节点为根的子树包含多少个节点，包含自己。
- `null`：对应课件中的 NIL。

这里每个数字出现一次就占一个节点，所以 `size = 左子树大小 + 右子树大小 + 1`。重复值也分别计数。

### 课件插入：x 往下找，y 记住上一个节点

`x` 从 root 出发，遇到空位置时结束。但此时 x 已经是 null，因此用 y 记住最后一个非空节点，作为新节点的父节点。

找到位置后，不仅要设置 `z.p = y`，还要设置 `y.left = z` 或 `y.right = z`。父子引用需要两边接好。

如果 y 是 null，说明树原本为空，新节点就是 root。

### 课件删除：重点是 Transplant

`transplant(u, v)` 用以 v 为根的子树替换以 u 为根的子树，只修改上方连接：

1. 让 u 原来的父节点改为连接 v；如果 u 是根，则修改 root。
2. 如果 v 不为空，设置 `v.p = u.p`。

它不会自动修改 v 的左右孩子，调用它的 remove 方法要负责接好。

删除分三种情况：

- 没有左孩子：用右孩子接替，可以同时处理叶子节点。
- 没有右孩子：用左孩子接替。
- 两个孩子都有：找到右子树最小节点 y，让 y 接替 z。

如果 y 不是 z 的直接右孩子，要先用 y 的右孩子填补 y 原来的位置，再让 y 接上 z 的右子树。最后用 y 替换 z，接上 z 的左子树。

删除时的 size 也要维护：y 从原位置移走后，更新它原位置的祖先；y 到新位置并接好孩子后，再从 y 向上更新。

### 我这次写错的地方：rank 的 < 和 <=

我最初写的是：

```java
if (k < x.key) {
    x = x.left;
} else {

    x = x.right;

```

问题在于 k 等于当前值时，会进入 else，把当前节点也计入答案。这样算出来的是“小于等于 k 的数量 + 1”。

但题目只统计严格小于 k 的数，所以要改为：

```java
if (k <= x.key) {
    x = x.left;
} else {
    ans += size(x.left) + 1;
    x = x.right;
}
```

最小反例：树里只有一个 5，查询 rank(5)。正确答案是 1，原代码却返回 2。

```java
import java.io.*;
import java.util.StringTokenizer;

public class Main {
    static class FastReader {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        StringTokenizer st;
        int nextInt() throws IOException {
            while (st == null || !st.hasMoreTokens()) {
                st = new StringTokenizer(br.readLine());
            }
            return Integer.parseInt(st.nextToken());
        }
    }

    static class Node {
        int key;
        int size = 1;
        Node left, right, p;
        Node(int key) { this.key = key; }
    }

    static Node root;
    static int size(Node x) { return x == null ? 0 : x.size; }

    static void update(Node x) {
        while (x != null) {
            x.size = size(x.left) + size(x.right) + 1;
            x = x.p;
        }
    }

    static void insert(Node z) {
        Node x = root, y = null;
        while (x != null) {
            y = x;
            if (z.key < x.key) x = x.left;
            else x = x.right;
        }
        z.p = y;
        if (y == null) root = z;
        else if (z.key < y.key) y.left = z;
        else y.right = z;
        update(z);
    }

    static void transplant(Node u, Node v) {
        if (u.p == null) root = v;
        else if (u == u.p.left) u.p.left = v;
        else u.p.right = v;
        if (v != null) v.p = u.p;
    }

    static Node min(Node x) {
        while (x.left != null) x = x.left;
        return x;
    }

    static Node search(Node x, int k) {
        while (x != null && k != x.key) {
            if (k < x.key) x = x.left;
            else x = x.right;
        }
        return x;
    }

    static void remove(Node z) {
        if (z.left == null) {
            Node oldP = z.p;
            transplant(z, z.right);
            update(oldP);
        } else if (z.right == null) {
            Node oldP = z.p;
            transplant(z, z.left);
            update(oldP);
        } else {
            Node y = min(z.right);
            if (y != z.right) {
                Node oldP = y.p;
                transplant(y, y.right);
                update(oldP);
                y.right = z.right;
                y.right.p = y;
            }
            transplant(z, y);
            y.left = z.left;
            y.left.p = y;
            update(y);
        }
    }

    static int rank(int k) {
        Node x = root;
        int ans = 1;
        while (x != null) {
            if (k <= x.key) {
                x = x.left;
            } else {
                ans += size(x.left) + 1;
                x = x.right;
            }
        }
        return ans;
    }

    static int kth(int k) {
        Node x = root;
        while (x != null) {
            int r = size(x.left) + 1;
            if (k == r) return x.key;
            else if (k < r) x = x.left;
            else {
                k -= r;
                x = x.right;
            }
        }
        throw new IllegalArgumentException("Invalid");
    }

    static int predecessor(int k) {
        Node x = root, ans = null;
        while (x != null) {
            if (x.key < k) {
                ans = x;
                x = x.right;
            } else x = x.left;
        }
        return ans.key;
    }

    static int successor(int k) {
        Node x = root, ans = null;
        while (x != null) {
            if (x.key > k) {
                ans = x;
                x = x.left;
            } else x = x.right;
        }
        return ans.key;
    }

    public static void main(String[] args) throws IOException {
        FastReader in = new FastReader();
        int n = in.nextInt();
        StringBuilder output = new StringBuilder();
        for (int i = 0; i < n; i++) {
            int opt = in.nextInt(), x = in.nextInt();
            switch (opt) {
                case 1: insert(new Node(x)); break;
                case 2: remove(search(root, x)); break;
                case 3: output.append(rank(x)).append('\n'); break;
                case 4: output.append(kth(x)).append('\n'); break;
                case 5: output.append(predecessor(x)).append('\n'); break;
                case 6: output.append(successor(x)).append('\n'); break;
            }
        }
        System.out.print(output);
    }
}
```

### 能从这道题学到什么

1. **把伪代码逐步翻译成 Java。** 课件中的 NIL 对应 null，节点属性对应对象字段，T.root 对应 root。先保持课件的控制流程，再补题目需要的数据。
2. **维护额外信息来扩展结构。** 普通 BST 可以查找、插入、删除，加上 size 才能沿搜索路径查询排名和第 k 小。
3. **查询排名和查询第 k 小方向相反。** rank 累计跳过了多少个更小的数；kth 根据左子树大小决定去哪边，并在向右时扣掉跳过的数量。
4. **结构变化后要更新父链。** 孩子变了，祖先的 size 也可能改变。删除中的两次更新分别维护旧位置和新位置。
5. **区分节点后继和严格数值后继。** 删除时用右子树最小节点保持中序顺序，重复值情况下它可能与被删值相等；操作 6 却必须返回严格大于查询值的数，因此使用严格比较单独搜索。
6. **用最小反例检查边界。** “严格小于”遇到相等时不能统计。只有一个 5 的例子，就能定位 rank 的错误。
7. **普通 BST 不保证平衡。** 每次操作 O(h)，最坏树高 O(n)，总时间最坏 O(n²)，空间 O(n)。不能把普通 BST 的单次复杂度直接写成 O(log n)。
