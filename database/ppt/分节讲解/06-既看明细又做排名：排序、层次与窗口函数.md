这节课沿着两个问题前进：结果怎样按人想要的顺序展示？如果我既要每部电影的明细，又要它在所属国家里的位置或统计信息，怎么办？

## 1. 查询得到同一批电影，为什么每次显示顺序可能不同（p2–15）

没有 ORDER BY，就没有结果顺序保证。存入顺序、上次看见的顺序、GROUP BY 看起来排过序，都不能代替明确排序。

```sql
SELECT movieid, title, country, year_released
FROM movies
ORDER BY country ASC, year_released DESC, movieid ASC;
```

先按国家，同国家按年份从新到旧，同年份再按 movieid。后面的排序键只打破前面相同的情况；每列的 ASC/DESC 分别生效。

为什么加 ID？如果同年有多部片，只按年份，内部先后没有明确规则。临时展示可能不重要，分页和选前 N 条时就很重要。

### 1.1 排的是数值、日期，还是已经转成的文字

课件提醒：把日期 `TO_CHAR(...,'MM/DD/YYYY')` 成字符串用于显示，再按这个别名排序，可能先按月日字符排，年份顺序就乱了。显示可格式化，排序继续用原始日期列。

文本按什么规则排由 collation 决定，重音、大小写、语言习惯会影响比较和排序，不能假定所有环境都按一个字符编码顺序。

NULL 默认排前排后也因产品而不同。补充 PostgreSQL 写法 `ORDER BY died NULLS LAST` 可明确放最后；要写跨产品方案，可用 `CASE WHEN died IS NULL THEN 1 ELSE 0 END, died`。

## 2. 业务顺序不是字母顺序，怎样办（p16–18）

Credits 未来包含 D 导演、P 制片人、A 演员。想按“导演、制片人、演员”展示，升序是 A/D/P，降序是 P/D/A，都不对。

解决：先把业务规则转换为可以排序的数字：

```sql
SELECT movieid, peopleid, credited_as
FROM credits
ORDER BY movieid,
         CASE credited_as
             WHEN 'D' THEN 1
             WHEN 'P' THEN 2
             WHEN 'A' THEN 3
             ELSE 4
         END,
         peopleid;
```

这是 CASE 在展示规则里的应用。若建表时 CHECK 只允许 A/D，要先允许新身份 P 再录入；查询示例不表示约束会自己改变。

## 3. 排完只看一小段：Top N 与分页（p19–26）

网站每页 10 条，第三页要跳过前 20 条，再取 10 条：

```sql
-- PostgreSQL / MySQL / SQLite 常见写法
SELECT movieid, title, year_released
FROM movies
ORDER BY year_released DESC, movieid
LIMIT 10 OFFSET 20;
```

OFFSET 是跳过多少行，因此这里取第 21–30 行。不是第 20–30 行，也不是“第三页就 offset 3”。

课件还展示 `FETCH FIRST ... ROWS ONLY` 与 SQL Server TOP。理解为“先定义排序，再取需要的范围”，语法按产品使用。

补充：稳定排序仍不能自动解决两次分页请求之间有数据新增的问题；快照或基于游标的分页属于进一步设计。本课件重点是基本 LIMIT/OFFSET。

## 4. 按时间排序还不够：评论回复有父子关系（p27–35）

情况：10:29 的评论有两条回复，10:31 又有另一条独立评论。纯按时间列，回复会散在不同位置，不容易看出在回复谁。

解决思路之一：给每条评论保存父评论 ID，并记录祖先路径，把同一分支放一起。课件展示物化路径：

```text
根评论 1723：键 000001723
它的回复 1732：键 000001723000001732
1732 的回复 1733：键 000001723000001732000001733
```

固定宽度很重要，否则字符串 `'10'` 可能排在 `'2'` 前面，拼路径排序就会混乱。路径保存祖先信息，读取方便，但移动一个分支可能要更新很多后代路径，这是补充的设计代价。

课件还展示 Oracle `START WITH ... CONNECT BY ... PRIOR ... ORDER SIBLINGS BY ...` 来表达树形遍历。p35 只是预告递归查询，并未系统展开递归 CTE；第 7 节也没有展开，当前笔记不冒充老师已经讲完递归机制。

类似需求还有零件组成、组织结构。它们都不是“把一个时间列排序”能完整表达的。

## 5. GROUP BY 丢掉明细，窗口函数怎样补上（p36–44）

需求：“每个国家最早电影的标题和年份。”

```sql
SELECT country, MIN(year_released)
FROM movies GROUP BY country;
```

它能算最早年份，但一行变成一个国家，标题已经被压掉。旧办法是把结果连回 Movies，连接条件同时包括国家和年份：

```sql
SELECT m.movieid, m.country, m.title, m.year_released
FROM movies m
JOIN (
    SELECT country, MIN(year_released) AS earliest_year
    FROM movies GROUP BY country
) x ON x.country = m.country AND x.earliest_year = m.year_released;
```

为什么两列都要连？只连年份会把别国同年电影也配进来。同国同年有多部最早片，应保留并列。

窗口函数提供另一条思路：**保留每部电影那一行，同时在旁边标上它所在组的统计值。**

```sql
SELECT movieid, country, title, year_released,
       MIN(year_released) OVER (PARTITION BY country) AS earliest_year
FROM movies;
```

假设某国电影年份是 2000、2005、2005，每一行旁边的 earliest_year 都是 2000，仍有三行。GROUP BY 会压成一行，窗口不会。

再套一层，只留“自己年份等于组最早年份”的电影：

```sql
SELECT movieid, country, title, year_released
FROM (
    SELECT movieid, country, title, year_released,
           MIN(year_released) OVER (PARTITION BY country) AS earliest_year
    FROM movies
) x
WHERE year_released = earliest_year;
```

`PARTITION BY` 决定分哪几组；这里没有窗口内 ORDER BY，因为求整个国家的最小年份不需要次序。`OVER()` 表示把当前输入整体当成一个分区。

## 6. 同一个排除条件，放里层还是外层，题意会变（p45–50）

某国只有 A(2000)、B(2005)，你不想显示 A。

第一种：先排除 A，再算最早。输入只剩 B，最早变 2005，B 被选中。这回答“剩余电影里最早的”。

第二种：先对所有电影算最早 2000，再筛最早且不是 A。B 不是最早，A 又被排除，整个国家没有结果。这回答“真正最早的电影，只是不显示 A”。

```text
WHERE 在计算窗口的里层：改变参加比赛的人
WHERE 在窗口算完的外层：不改比赛，只决定展示谁
```

窗口作用于同层 FROM/WHERE、以及存在时 GROUP BY/HAVING 产生的行，不是永远作用于整张原始表。在 PostgreSQL 中不能直接在同层 WHERE 使用窗口结果，通常套子查询后筛；窗口也可以用于 ORDER BY，课件“只能在 SELECT”是简化。[PostgreSQL 窗口教程](https://www.postgresql.org/docs/current/tutorial-window.html)

## 7. 分组计数还要看占总量百分比（p51–53）

先让结果一行一国，算出 cnt，再用整体窗口 SUM 得总数：

```sql
SELECT country, cnt,
       100.0 * cnt / NULLIF(SUM(cnt) OVER (), 0) AS percentage
FROM (
    SELECT country, COUNT(*) AS cnt
    FROM movies GROUP BY country
) x;
```

`100.0` 提醒使用小数计算，`NULLIF(...,0)` 处理分母为零。若还要列零电影国家，使用第 5 节的完整国家表 LEFT JOIN 计数，再在其结果上计算总量。

课件还展示 CROSS JOIN 一个全库 COUNT 的单行结果。右侧恰好一行时，每个国家都配上同一个总数，不会增加国家行数。若右侧不是一行，CROSS JOIN 就会乘开，不要照模板忘记它的行数前提。

## 8. 排名看起来一样，遇到并列才知道选哪个（p54–67）

按上映年降序，某国电影是 A(2024)、B(2024)、C(2022)、D(2020)：

| 电影 | ROW_NUMBER（同年按 ID） | RANK（只按年份） | DENSE_RANK（只按年份） |
| --- | --- | --- | --- |
| A | 1 | 1 | 1 |
| B | 2 | 1 | 1 |
| C | 3 | 3 | 2 |
| D | 4 | 4 | 3 |

ROW_NUMBER 给每行独立序号；RANK 并列同名次，后面留空档；DENSE_RANK 并列同名次，后面接着排。

### 8.1 每国最新两部：按行取

```sql
SELECT movieid, country, title, year_released
FROM (
    SELECT movieid, country, title, year_released,
           ROW_NUMBER() OVER (
               PARTITION BY country
               ORDER BY year_released DESC, movieid
           ) AS rn
    FROM movies
) x
WHERE rn <= 2
ORDER BY country, rn;
```

足够多时每国两行，A/B 被选中。ID 用来明确同年先后。窗口内 ORDER BY 是决定编号的规则，外层 ORDER BY 才保证最终展示顺序。

### 8.2 每国最新两个不同年份：按年档次取

换成：

```sql
DENSE_RANK() OVER (
    PARTITION BY country ORDER BY year_released DESC
) AS year_rank
```

再在外层筛 `year_rank <= 2`，得到 A/B/C，共三部。**这里别把 movieid 加到窗口排序里**，否则同年也因 ID 不同失去并列，就不能代表同一年档次。最终展示想稳定，可以在最外层加 ID。

`RANK <= 2` 在此只留下 A/B，因为 C 的名次是 3。问“前 K 名含并列”与“前 K 个不同值”要先确认题意。

课件强调排名要有排序规则，这是解题要求；某些数据库允许 `ROW_NUMBER() OVER()`，但没有明确顺序就不适合解释“最新”。

## 9. 两个不要照抄的简化说法

课件说 SQLite 不支持窗口函数，这已过时：从 3.25.0 起支持。[SQLite 官方说明](https://www.sqlite.org/windowfunctions.html)

补充：窗口聚合若增加 ORDER BY，默认窗口帧可能从“整组”变成“截至当前行及其同排序值行”，不能随手给所有 OVER 都加 ORDER BY。求整组总量可保留 `OVER(PARTITION BY ...)`；本课件没有系统展开窗口帧，使用时应再核对。[PostgreSQL 窗口函数文档](https://www.postgresql.org/docs/current/functions-window.html)

性能方面，窗口函数不保证一定比聚合后连接快，“排序时顺便算几乎无成本”也不是通用结论。先保证结果含义正确，再根据数据和计划比较。

## 10. 自测

1. 同国同年有三部片，“最新两部”与“最新两个年份”一样吗？<br>
   答：不一样，前者最多取两行，后者可能包含很多行。
2. 排除最早片放内层还是外层，哪种会把第二早升为最早？<br>
   答：内层先排除，再计算窗口。
3. 窗口里排好序，输出一定按这个序显示吗？<br>
   答：不保证，最终输出还要外层 ORDER BY。
4. DENSE_RANK 按年份和唯一 ID 排序，还会让同年并列吗？<br>
   答：不会，排序键组已经不同，年份档次含义被破坏。

本节学会后，你应能分别解释“分哪些组”“每行还代表什么”“按什么比较先后”“同值怎样并列”“筛选发生在计算前还是后”。
