# 第 4 节：统计为什么算错——去重、聚合与连接

> [返回分节目录](README.md) · [大总结](../数据库原理复习总结.md) · [上一节](03-怎样准确挑出记录：条件、日期、NULL与CASE.md) · [下一节](05-缺记录也要保留：外连接、集合与子查询.md)

这节的核心问题是：**你现在的一行究竟代表一部片、一个国家，还是一次参演？** 只要中途换了含义，却仍按原来的含义计数，SQL 就容易悄悄算错。

## 1. 只取国家列，为什么满屏都是 us（p2–7）

原表一行一部电影。若有三部美国片，`SELECT country FROM movies` 就返回三个 us，因为 SQL 默认保留这三行，并不会因为你只显示国家就自动合并。

先确认你在问什么：

- “有哪些国家？”需要不同国家的名单。
- “每国有多少部片？”需要按国家统计。

第一种情况用 DISTINCT：

```sql
SELECT DISTINCT country FROM movies;
```

如果写 `DISTINCT country, year_released`，去重对象是**整组列值**。`(us,2000)` 和 `(us,2001)` 仍是两行。同理，`DISTINCT title` 可能误合并同名的不同电影，不能把它当万能去错按钮。

## 2. 想知道每国多少部片，就把电影按国家装进小堆（p8–18）

先用三条数据手算：

```text
电影 A：us，2000
电影 B：us，2000
电影 C：gb，2001
```

`GROUP BY country` 把 A/B 放一堆，C 放另一堆；`COUNT(*)` 数每堆多少行。

```sql
SELECT country, COUNT(*) AS movie_count
FROM movies
GROUP BY country;
```

结果是 `(us,2)`、`(gb,1)`。此时一行代表一个国家，不再代表某部电影。

为什么不能随便加一个 title？美国这一堆有 A 和 B，该显示谁？SQL 需要你给出确定规则。练习中遵守：SELECT 中的非聚合列都放入 GROUP BY；部分数据库可以利用函数依赖等规则接受额外列，但别据此随便挑一行。

若按 `country, year_released` 分组，一行变成“一个国家的一个年份”，分组粒度又变了。

`MIN(year_released)` 得最早年份，**不会自动带出该年份对应的 title**。找标题要把统计结果连接回明细，或使用第 6 节窗口函数。

## 3. 条件是管一行，还是管一堆（p18–22）

需求：“只看 2000 年以来的电影，找至少有两部的国家。”

```sql
SELECT country, COUNT(*) AS movie_count
FROM movies
WHERE year_released >= 2000
GROUP BY country
HAVING COUNT(*) >= 2;
```

先 WHERE 挑电影，再 GROUP BY 分堆，最后 HAVING 看每堆统计值。`WHERE COUNT(*) >= 2` 不合适，因为还没分堆就没有这堆的大小。

课件先用外层查询筛聚合结果，再引出 HAVING 作为更直接的写法。这延续了第 3 节“先产出中间表，再继续筛”的思路。

课件讲排序成本，是为了说明聚合可能需要准备工作。补充：实际也可能用哈希聚合，`GROUP BY` 不保证有序；也不能靠“某产品一定帮你改写、另一产品一定不会”判断性能，要看执行计划。理解逻辑顺序与推断物理执行方式是两件事。

## 4. 空值对统计有什么影响（p23–29）

假设 `died` 是 `[1980, NULL, 2000]`：

| 表达式 | 结果 | 数的是什么 |
| --- | --- | --- |
| COUNT(*) | 3 | 三条记录 |
| COUNT(died) | 2 | 死亡年已知的记录 |
| COUNT(DISTINCT died) | 2 | 不同的非空死亡年 |
| AVG(died) | 1990 | 两个已知值的平均 |

常见聚合如 SUM/AVG/MIN/MAX 忽略 NULL；COUNT(*) 数行。即使一行每列都是 NULL，它仍是一行，课件 p26 关于“一行必有非空值”的解释不能作为通则。

若 `[10,NULL,20]` 是金额，AVG 为 15，不是 10。将 NULL 当 0 是额外业务选择，`AVG(COALESCE(amount,0))` 会得到不同含义。

补充：没有输入行时，不带 GROUP BY 的 COUNT(*) 返回一行 0，SUM 通常返回一行 NULL；有 GROUP BY 时没有任何分组，通常返回零行。

## 5. “既演又导”为什么不能直接数两行（p30–33）

人物 11 的 Credits 记录可能是：

```text
(电影 1, 人物 11, A)
(电影 2, 人物 11, A)
```

虽然两行，却只当过演员。直接 `GROUP BY peopleid HAVING COUNT(*)=2` 统计的是参演记录数。

先把问题翻译为：“这个人出现过 A 和 D 两种身份，不要求同一部电影。” movieid 在此不重要，先限定并去重身份，再计数：

```sql
SELECT peopleid
FROM credits
WHERE credited_as IN ('A', 'D')
GROUP BY peopleid
HAVING COUNT(DISTINCT credited_as) = 2;
```

为什么限定 A/D？未来还有 P（制片人），不能让“演员 + 制片人”误充“演员 + 导演”。课件用“先 DISTINCT 两列，再分组计数”实现同样推理。

如果题目要求“在同一部电影里既演又导”，分组粒度应改成 `(movieid, peopleid)`。中文只多几个字，SQL 的一行含义就变了。

## 6. 表拆开了，查询时怎样拼回来（p34–54）

情况：Movies 有国家代码，Countries 才有国家名。需要同时显示电影和国家名。

```sql
SELECT m.movieid, m.title, c.country_name
FROM movies m
JOIN countries c ON c.country_code = m.country;
```

逻辑上可以想成先考虑两张表所有配对，再留下代码匹配的组合。若两边是 3 行和 4 行，所有配对是 12 行。但优化器不一定真的生成整张大表，它可以使用索引或其他连接算法。

### 6.1 JOIN 不会自动识别外键替你补条件

`ON` 明确谁与谁匹配。即使两列都叫 name，也不代表它们描述同一个东西。课件因此提醒 NATURAL JOIN 会依赖同名列，后续结构变化可能改变含义。写明确的 ON 和短表别名更容易检查。

`m.country = c.country_code` 两列名称不同，照样能连。反过来，两列同名但不说明来源，可能语法歧义，甚至写成无意义条件。

### 6.2 连接以后，行数会不会增加

电影连到国家，国家代码唯一，每部电影最多配一个国家。电影连到 Credits，一部片有 5 条演职员记录，就会展开成 5 行。

```text
电影 A + 演员甲
电影 A + 演员乙
电影 A + 导演丙
```

这三行不是程序出错，而是在描述三个联系。但此时 `COUNT(*)` 不能再解释为“三部电影”。统计电影可能需要 `COUNT(DISTINCT m.movieid)`，或者先将右侧降到一部片一行，或者改用 EXISTS。

SQL 允许连接带重复的结果，不能把课件“必须是关系”的教学提醒误当成语法要求。真正要问的是：保留这些重复是否符合当前任务。

## 7. 多表连接与自连接，都是同一个匹配思路（p55–69）

“英国电影及其导演”需要三个表：电影给国别和标题，Credits 告诉谁是导演，People 给姓名。

```sql
SELECT m.movieid, m.title, m.year_released,
       p.peopleid, p.first_name, p.surname
FROM movies m
JOIN credits c ON c.movieid = m.movieid
JOIN people p ON p.peopleid = c.peopleid
WHERE m.country = 'gb'
  AND c.credited_as = 'D';
```

保留两种 ID，是为了让同名电影、同姓导演仍能分清。两兄弟合作导演同一片时，`DISTINCT title,surname` 可能把两个人压成一个。去掉表面重复前，先问它们是否代表不同真实对象。

自连接也不神秘：假设扩展 People 有 fatherid，一份别名代表孩子，另一份代表父亲：

```sql
-- 仅适用于已增加 fatherid 的扩展模型
SELECT child.peopleid, child.surname,
       father.peopleid AS father_id, father.surname AS father_surname
FROM people child
JOIN people father ON father.peopleid = child.fatherid;
```

这是同一张表扮演两个角色。暂时找不到父亲匹配的人会消失，下一节外连接才解决保留问题。

多张表的普通内连接在适当条件下可以调整书写顺序，优化器也会选择执行顺序。但“书写第一张表”不等于“它的所有行一定保留”；外连接则必须认真考虑保留哪边。

## 8. 自测

1. A 在两部片都当演员，用 COUNT(*)=2 能证明既演又导吗？<br>
   答：不能，必须数限定后的不同身份。
2. 一部电影连出 10 个演员，COUNT(*) 是几？<br>
   答：10，它数的是连接后的行。
3. SELECT country, MIN(year), title 是否自动带出最早片名？<br>
   答：不可以这样假定，最小年份和对应明细需要额外关联。
4. 同姓的两个导演被 DISTINCT 合并，是正确去重吗？<br>
   答：若任务是列导演人物，就丢失信息，应保留人物身份。

每写一层查询，给中间结果补一句中文：“现在一行代表……”。这句比机械增加 DISTINCT 更能防止统计错误。
